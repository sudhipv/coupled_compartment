# Coupled Compartment Models With Mobility

This repository hosts the full workflow used to study COVID-19 transmission in Ontario Public Health Units (PHUs) with spatial coupling. It contains the forward SEIRD-style models, the mobility tensors that move people between PHUs, the data needed for inference, and the tooling for manual tuning, maximum-likelihood estimation (MLE), and Transitional MCMC (TMCMC) using negative-binomial likelihoods.

## Highlights
- Deterministic SEIRD forward models for single PHUs or coupled PHUs (two and three region cases in `forward_model/`).
- Multiple parameter-estimation paths: manual tuning (`manual_tuning/`), grid/MLE (`mle/`), and Bayesian TMCMC samplers (`mcmc/`).
- Rich data assets covering Ministry of Health case counts (`PHU_Data/`) and weekly mobility/flow tensors (`mobility_tensor/`) alongside synthetic truth sets (`data/`).
- Ready-to-run scripts and notebooks for generating predictions and figures, plus a Slurm script (`mcmc/run_cluster.sh`) for scaling TMCMC runs on clusters.

## Environment & Dependencies
- Python 3.9+ (cluster script currently loads Python 3.11.5).
- Core scientific stack: `numpy`, `scipy`, `matplotlib`.
- `mpi4py` for MPI-based TMCMC runs; TMCMC scripts can also fall back to `multiprocessing`.
- JupyterLab/Notebook for the `.ipynb` files.
- Optional: `pandas` for CSV wrangling in notebooks.

The `mcmc/*/tmcmc_mod` directory vendors a lightly modified copy of [mukeshramancha/transitional-mcmc](https://github.com/mukeshramancha/transitional-mcmc). No extra installation is needed beyond ensuring the folder stays on the Python path when executing scripts from within `mcmc/coupled_phu` or `mcmc/single_phu`.

## Repository Layout
- `PHU_Data/` – Daily case count CSVs for each PHU, lookup tables (`phu_list.csv`, `population_by_phu.csv`), and a `PHU_sept1-feb28.ipynb` notebook for collating periods of interest.
- `mobility_tensor/` – Raw and processed mobility resources: weekly `Flows.csv`, stochastic matrices (see `stochastic_Tor_*` folders), helper notebooks (`Stochastic-matrix.ipynb`, `timetrace.ipynb`), and sanity-check plots.
- `data/` – Synthetic datasets (`*_synth_truth_all.csv`), prior statistics, and archived experiments (`data/old/*`).
- `forward_model/` – Two and three PHU forward-simulator notebooks (`2phu_forward.ipynb`, `3phu_forward.ipynb`).
- `manual_tuning/` – Manual parameter sweep notebooks (`manual_tune.ipynb`, `Infection_data_apr1-dec31.ipynb`, `plt_data.ipynb`), supporting PDFs, and generated figures.
- `mle/` – Negative-binomial MLE notebooks for coupled (`mle/coupledPHU/Nbinomial`) and single PHU cases (`mle/singlePHU/Nbinomial`) plus recorded optimizer logs.
- `mcmc/` – TMCMC implementations:
  - `single_phu/` – Scripts such as `singlephu_mcmc_NB_durham.py` and notebooks for Toronto/Durham predictions; includes a local `tmcmc_mod/`.
  - `coupled_phu/` – `coupled_mcmc_NB.py`, coupled prediction notebooks, and the same TMCMC backend.
  - `predictions_1phu_BRANDON_initial.ipynb` and `run_cluster.sh` live at the top level for additional scenarios and Slurm submission.
- `figs/` – Organized output figures from MLE, MCMC, model comparison, and prediction runs.
- `manual_tuning/figs/` and other nested `figs/` folders – Intermediate plots generated by notebooks.
- `status.txt` – Simple, human-maintained log of the latest experiments.
- `LICENSE` – GPL-3.0 license covering the repository.

## Data & Mobility Inputs
1. **PHU Case Data** – Use the CSVs in `PHU_Data/` with the helper notebook to build aligned time series. `population_by_phu.csv` is the population reference used by the forward simulators.
2. **Mobility Tensor** – Weekly flows between PHUs are stored in `mobility_tensor/Flows.csv` and converted to time-dependent stochastic matrices (`mobility_tensor/stochastic_*`). The coupled models read these tensors to couple the compartmental states (see `coupled_mcmc_NB.py` near the `Mobility tensor` section).
3. **Synthetic Truth Sets** – `data/*_synth_truth_all.csv` and `muVec_*` files provide reproducible benchmarks for testing estimation pipelines.

## Typical Workflow
1. **Prepare Inputs**
   - Clean case counts with `PHU_Data/PHU_sept1-feb28.ipynb`.
   - Generate or update mobility tensors via `mobility_tensor/Stochastic-matrix.ipynb` or the deterministic scripts inside `mobility_tensor/stochastic_*`.
2. **Forward Simulation**
   - Prototype dynamics with `forward_model/2phu_forward.ipynb` or `3phu_forward.ipynb`. These notebooks define the SEIRD system, control change points, and mobility coupling.
3. **Manual Tuning**
   - Use `manual_tuning/manual_tune.ipynb` and the reference PDFs to bracket feasible parameter regions before automated inference.
4. **Maximum Likelihood (Negative Binomial)**
   - Run `mle/singlePHU/Nbinomial/1phu_sequential_MLE_NB_*.ipynb` for single-PHU fits.
   - Use `mle/coupledPHU/Nbinomial/2phu_grid_search_NB.ipynb` and `2phu_allparam.ipynb` to identify MAP seeds for the coupled case.
   - Text files such as `mle/mle_lbfgs_out_coupled_tor_dur_REAL.txt` capture optimizer traces.
5. **Bayesian TMCMC**
   - Configure priors in `mcmc/single_phu/singlephu_mcmc_NB_*.py` or `mcmc/coupled_phu/coupled_mcmc_NB.py`. Each script specifies:
     - `parallel_processing` (`multiprocessing` for local runs, `mpi` for clusters),
     - Lower/upper bounds derived from MLE results,
     - Paths to data (`PHU_path`, `mobpath`, etc.).
   - Launch locally, e.g.:
     ```bash
     cd mcmc/single_phu
     python singlephu_mcmc_NB_durham.py
     ```
     Ensure the hard-coded `PHU_path`, `figpath`, `datapath`, and `mobpath` point to your environment.
   - For MPI jobs, adapt `mcmc/run_cluster.sh` with your account, email, and desired script (currently set to `singlephu_8param.py`) and submit through `sbatch`.
6. **Post-processing**
   - Prediction notebooks (`mcmc/*/predictions_*.ipynb`) read TMCMC samples and produce figures stored under `figs/`.
   - Use `figs/methods`, `figs/mcmc`, and `figs/predictions` to compare inference strategies side by side.

## Notes & Tips
- All TMCMC scripts fix the RNG seed (`np.random.seed(106)`) to guarantee reproducibility unless you change it.
- Negative-binomial likelihoods live inside the TMCMC scripts; edit them if you switch observation models.
- The `tmcmc_mod` package expects to be imported relative to the script directory. Run scripts from within `mcmc/single_phu` or `mcmc/coupled_phu` to avoid `ModuleNotFoundError`.
- `status.txt` gives a human-readable snapshot of the latest real vs synthetic runs. Update it when starting or finishing experiments to keep collaborators aligned.
